1. Criterion 1: Problem Definition & Automata Specification (1 Mark)

1.1 Problem Statement

Formal Language and Automata Theory is a foundational core of theoretical computer science. However, students frequently struggle to connect abstract mathematical definitions—such as state tuples, transition functions (δ), and instantaneous configurations—with concrete algorithmic processes. Traditional teaching relies on static blackboard diagrams and manual pen-and-paper tracing, which is labor-intensive and prone to calculation error.

Furthermore, existing desktop software (such as JFLAP) relies on outdated Java runtimes, possesses complex interfaces, and lacks modern bidirectional synchronization between transition tables and state diagrams.

1.2 Project Objectives

  • Zero-Installation Accessibility: Develop a clean, client-side web application running natively in modern browsers.
  • Dual Synchronized Input Modalities: Allow students to construct automata visually on an SVG canvas or numerically via a synchronized matrix transition table.
  • Strict Formal Validation: Enforce complete DFA properties (δ as a total function) and explicitly highlight any missing transitions δ(q, a).
  • Granular Step-by-Step Visualization: Provide interactive stepping with node and edge highlights, accompanied by an instantaneous execution trace log.

1.3 System Inputs & Outputs

  • Inputs: State set Q, input alphabet Σ, unique initial state q0, accepting state set F, transition mappings δ: Q × Σ → Q, and user string w ∈ Σ*.
  • Outputs: Dynamic SVG state diagram, synchronized transition table, validation error list, real-time node/edge highlights, and execution decision (ACCEPTED, REJECTED, or INVALID INPUT).

1.4 Formal Automata Specification (5-Tuple)

A Deterministic Finite Automaton (DFA) is formally defined as a 5-tuple:

M = (Q, Σ, δ, q0, F)
  1. Q: A finite, non-empty set of internal states: Q = {q0, q1, ..., qn-1}.
  2. Σ: A finite, non-empty set of input symbols (the alphabet).
  3. δ: The state transition function, defined as a total function mapping:
    δ : Q × Σ → Q
    In a complete DFA, for every state q ∈ Q and every symbol a ∈ Σ, there exists exactly one deterministic target state p ∈ Q.
  4. q0 ∈ Q: The unique designated start (initial) state.
  5. F ⊆ Q: The set of final (accepting) states.

Extended Transition Function (δ̂):

  • Base condition: δ̂(q, ε) = q (where ε is the empty string)
  • Recursive step: δ̂(q, wa) = δ(δ̂(q, w), a) for all w ∈ Σ* and a ∈ Σ

A string w ∈ Σ* is accepted if and only if δ̂(q0, w) ∈ F; otherwise, it is rejected.

3.2 Input-Processing-Output (IPO) Workflow

  • Input: User specifies Q, Σ, q0, F, transitions δ (via table or visual selector), and candidate string w.
  • Processing:
    1. Model Validation: Check that every (q, a) has an explicit target in Q.
    2. Input Validation: Verify every character in w belongs to Σ.
    3. Simulation Loop: Start at q = q0. For each symbol a ∈ w, compute q ← δ(q, a), log step to history, and highlight active SVG nodes/edges.
    4. Acceptance Check: If terminal state q ∈ F, string is ACCEPTED; else REJECTED.
  • Output: Highlighted SVG graph, line-by-line execution trace table, and acceptance result banner.

4. Criterion 4: Algorithm Selection & Correctness (1 Mark)

4.1 DFA Completeness Validation Algorithm

ALGORITHM ValidateDFA(Q, Sigma, delta, q0, F):
    errors = []
    IF |Q| == 0 THEN APPEND "State set Q cannot be empty" TO errors
    IF |Sigma| == 0 THEN APPEND "Alphabet Sigma cannot be empty" TO errors
    IF q0 is NULL OR q0 NOT IN Q THEN APPEND "Invalid initial state" TO errors
    
    FOR EACH f IN F:
        IF f NOT IN Q THEN APPEND "Final state not in Q" TO errors

    FOR EACH state q IN Q:
        FOR EACH symbol a IN Sigma:
            dest = delta(q, a)
            IF dest is NULL THEN
                APPEND "Missing transition delta(q, a)" TO errors
            ELSE IF dest NOT IN Q THEN
                APPEND "Transition points to nonexistent state" TO errors

    RETURN { isValid: (|errors| == 0), errors: errors }

4.2 Deterministic Simulation Algorithm

ALGORITHM SimulateDFA(M, inputString w):
    FOR EACH character ch IN w:
        IF ch NOT IN Sigma THEN RETURN ERROR("Invalid character not in alphabet")

    currentState = q0
    history = [ { step: 0, symbol: "—", state: currentState } ]

    FOR i = 0 TO length(w) - 1:
        sym = w[i]
        nextState = delta(currentState, sym)
        history.append({ step: i + 1, symbol: sym, from: currentState, to: nextState })
        currentState = nextState

    IF currentState IN F THEN
        RETURN { status: "ACCEPTED", history: history }
    ELSE
        RETURN { status: "REJECTED", history: history }

4.3 Computational Complexity

  • Time Complexity:
    • Validation: O(|Q| · |Σ|) — verifies each cell in the transition matrix exactly once.
    • Simulation: O(|w|) — looking up δ(q, a) in JavaScript hash map is O(1) constant time per character, yielding strictly linear time in string length.
  • Space Complexity: O(|Q| · |Σ|) to store the transition model, and O(|w|) auxiliary space for the step execution trace table.

4.4 Manually Solved Validation Example

Language: Binary strings over Σ = {0, 1} ending with the substring 01.

Formal Specification: Q = {q0, q1, q2}, Σ = {0, 1}, Start State = q0, F = {q2}.

State (Q) Input '0' Input '1' State Role in Language Recognition
→ q0 q1 q0 Start state; reset state when trailing symbol is '1'.
q1 q1 q2 Recognized trailing '0'; candidate for "01".
* q2 q1 q0 Accepting state; string successfully ends with "01".

Manual Trace for Input String w = 1101:

  1. Start at q0: Configuration (q0, 1101)
  2. Read '1': δ(q0, 1) = q0 ⇒ Configuration (q0, 101)
  3. Read '1': δ(q0, 1) = q0 ⇒ Configuration (q0, 01)
  4. Read '0': δ(q0, 0) = q1 ⇒ Configuration (q1, 1)
  5. Read '1': δ(q1, 1) = q2 ⇒ Configuration (q2, ε)
  6. String completely consumed. Current state is q2 ∈ F. Result: ACCEPTED.
